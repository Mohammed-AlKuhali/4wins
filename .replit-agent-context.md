# Standing instructions for Replit Agent

> **Read this file before doing anything else.** It contains everything you need to work autonomously through this project.

---

## What this repo is

4Wins is a mobile app for a daily four-pillar discipline ritual (Physical, Mental, Spiritual, Financial). The repo currently contains a complete planning + spec layer (`docs/`). Your job is to add the implementation layer — backend (`/`) and mobile (`apps/mobile/`) — by working through the tickets in `docs/tickets/`.

---

## Operating mode — autonomous build

You will work through the entire ticket queue **without further user input**, except when blocked. The user has explicitly said: "I don't want to paste anything." Honor that.

### Loop

```
1.  Read docs/tickets/README.md to find the next un-merged ticket
    in dependency order (Sprint 1 → Sprint 8). The dependency graph
    in that README is binding.
2.  Read the ticket file in full.
3.  Read every doc the ticket references (PRD §X, brand bible §Y).
4.  Implement the ticket.
5.  Self-verify: walk through every acceptance-criteria checkbox.
    Run the tests. State which pass.
6.  Run the rejection-list grep (see "Self-verification" below).
7.  If everything passes:
       a. git add the changed files (specific paths, never `git add .`)
       b. git commit with a clear message that references the ticket
       c. Move to step 1 with the next ticket.
8.  If anything is blocked:
       Stop. State the blocker plainly. Ask the user a single
       focused question. Wait for an answer.
9.  At end of each sprint (boundary defined in tickets/README.md),
    pause and post a summary: which tickets shipped, what was learned,
    what's next. Then continue to the next sprint without waiting.
```

### When to stop and ask

- The ticket spec is genuinely ambiguous and reasonable interpretations diverge.
- A required external resource isn't available (Anthropic API key, Apple developer account, etc.).
- You hit a tool / platform limitation that can't be worked around (e.g. you cannot run `eas build` from this environment).
- A previous ticket's work needs revision and you can't tell whether to revise it.

### When NOT to stop

- A test fails because of a bug — fix it and continue.
- The ticket's stack constraint is inconvenient — follow it anyway.
- You think a different design would be better — note it, follow the ticket.
- You finish a ticket — keep going to the next one.

## Stack — non-negotiable

**Backend** (repo root, when implementing `docs/tickets/backend/`):

- Node 22, ESM (`"type": "module"`)
- Hono v4+ — NOT Express, NOT Fastify, NOT Koa
- Postgres + Drizzle ORM with `postgres-js` driver — NOT Prisma, NOT pg, NOT Sequelize
- zod for validation
- vitest for tests
- TypeScript strict, NodeNext modules, `.js` extensions in source imports

**Mobile** (`apps/mobile/`, when implementing `docs/tickets/mobile/`):

- Expo SDK 53+
- expo-router (file-based)
- react-native-svg (for the Quad + glyphs)
- react-native-reanimated (for motion)
- @tanstack/react-query (server state)
- expo-apple-authentication + expo-auth-session (auth)
- expo-av (voice recording)
- expo-secure-store (token storage)
- expo-haptics (feedback)
- TypeScript strict
- NO nativewind, tamagui, gluestack, or any UI kit
- NO Lucide, Heroicons, or any external icon pack — pillar glyphs only

**If anything is missing in this environment, ask before substituting.** Don't silently swap to something else.

## Brand rejection list — applies to ALL code

Apply this checklist to every diff, including backend code, READMEs, error messages, and comments.

**Visual / code:**
- ❌ `indigo-500`, `violet-500`, `fuchsia-500` colors
- ❌ `linear-gradient(135deg, ...)` anywhere
- ❌ Mesh-gradient blob backgrounds
- ❌ Radial dotted-grid backgrounds
- ❌ `bg-white` + `text-slate-600` body copy
- ❌ Inter, Geist, or Satoshi typefaces
- ❌ Bento grid layouts
- ❌ Lucide / Heroicons / Tabler icons
- ❌ unDraw / Storyset / Lummi illustrations

**Verbal (any user-facing string, including error messages):**
- ❌ Exclamation marks
- ❌ "✨" or any decorative emoji
- ❌ "Hey [Name] 👋" / "amigo" / "bestie" / "buddy"
- ❌ "Build [thing] [adverb] with [emotion]" headlines
- ❌ "Get Started" — use specific verbs
- ❌ "manifest / unlock / level up / crush it / amplify"
- ❌ "you got this" / cheerleading
- ❌ "Don't break your streak!" / guilt copy
- ❌ "Are you sure you want to leave?" guilt modals
- ❌ "AI Coach" persona name

**Interaction:**
- ❌ Bottom tab bar with 5 items
- ❌ Separate Profile tab
- ❌ Pull-to-refresh on the daily ritual screen
- ❌ Carousel onboarding with dot pagination
- ❌ Badges, levels, XP, "Spiritual Warrior" titles
- ❌ Leaderboards
- ❌ Public sharing as default
- ❌ Streak freeze IAP
- ❌ Bounce animations on completion
- ❌ Confetti or particle effects on completion

The full source for these rules is `docs/03-brand.md §9`. When in doubt, default to the stricter interpretation.

## Self-verification before commit

For every ticket:

1. **Walk through every acceptance-criteria checkbox** in the ticket file. State which pass and which don't. If any don't, fix or stop.
2. **Run the tests.** Don't claim success without running them. If `npm test` fails, fix.
3. **Grep the diff against the rejection list.** Catch:
   - `indigo-500`, `violet-500`, `fuchsia-500`, `135deg`, `slate-600`, `Inter`, `Geist`, `Satoshi`
   - `!`, `✨`, "Hey ", "amigo", "bestie"
4. **Confirm stack constraints held.** No silent substitutions.

Only after all four pass, commit and move on.

## Commit conventions

- Use specific paths in `git add` (never `git add .`).
- Commit message format:
  ```
  T-NNN: <short imperative summary>

  <one-paragraph what + why>

  Acceptance criteria: all passed.
  Tests: <X passing>
  Rejection list: clean.
  ```
- One commit per ticket. Don't bundle multiple tickets in one commit.
- Don't push without the user's explicit go-ahead. Local commits only.
