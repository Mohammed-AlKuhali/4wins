# Standing instructions for Replit Agent

> If you (the Replit Agent) are working in this repo, read this file before any other action.

## What this repo is

4Wins is a mobile app for a daily four-pillar discipline ritual (Physical, Mental, Spiritual, Financial). The repo contains:

- A planning + spec layer (`docs/`) — concept, research, brand bible, PRD, tickets.
- An implementation layer (forthcoming, will be created by you, ticket by ticket) — backend (`/`) and mobile (`apps/mobile/`).

## How work is delivered

- The user assigns work as **one ticket at a time**, identified by a path like `docs/tickets/backend/T-001-replit-setup.md`.
- Each ticket is self-contained. Acceptance criteria are binding.

## Before implementing any ticket

Read these files in order:

1. `docs/tickets/README.md` — repo conventions + dependency graph.
2. `docs/03-brand.md §9` — the rejection list. **This applies to ALL code, including backend.** No emoji in user-facing strings, no exclamation marks, no marketing voice, no `indigo-500` / `violet-500` / `135deg` gradients, no Inter/Geist/Satoshi as type, no Lucide/Heroicons.
3. The specific ticket file.
4. Any `Implements PRD: §X.Y` sections referenced in the ticket header — open `docs/04-prd.md` and read those sections.
5. Any brand bible sections referenced — open `docs/03-brand.md`.

## Stack — non-negotiable

**Backend** (when implementing backend tickets, the repo root):
- Node 22, ESM (`"type": "module"`)
- Hono v4+ (NOT Express, NOT Fastify)
- Postgres + Drizzle ORM with `postgres-js` driver (NOT Prisma, NOT pg, NOT Sequelize)
- zod for validation
- vitest for tests
- All TypeScript, strict mode

**Mobile** (when implementing mobile tickets, `apps/mobile/`):
- Expo SDK 53+
- expo-router for navigation
- react-native-svg for the Quad + glyphs
- react-native-reanimated for motion
- @tanstack/react-query for server state
- expo-apple-authentication + expo-auth-session for auth
- expo-av for voice recording
- TypeScript strict
- NO nativewind, tamagui, gluestack, or any other UI kit
- NO Lucide, Heroicons, or any external icon pack — pillar glyphs only

If anything in the chosen stack is unavailable in your environment, **ASK**. Do not silently substitute.

## Self-verification

Before claiming a ticket is done:

1. Walk through every acceptance-criteria checkbox in the ticket. State which pass.
2. Run the tests if the ticket adds any. Don't claim success if tests didn't run.
3. Grep the diff for the rejection list (`docs/03-brand.md §9`):
   - `indigo-500`, `violet-500`, `fuchsia-500`, `135deg`, `slate-600`
   - Inter, Geist, Satoshi as primary type
   - "✨", "🚀", emoji in copy
   - Exclamation marks in user-facing strings
   - "Hey [Name] 👋" / "amigo" / "bestie" / "buddy" greetings
   - "Build [thing] [adverb] with [emotion]" headlines
4. If any criterion is partial, **say so**. Don't claim completion if it isn't.

## When in doubt

- About the stack → re-read this file's "Stack" section.
- About the brand → `docs/03-brand.md`. Especially §3 (voice/copy), §4 (color), §9 (rejection list).
- About a screen or flow → `docs/04-prd.md` §2 (flows) or §3 (screens).
- About data shapes or APIs → `docs/04-prd.md` §5 (data model) or §6 (API surface).
- About what's deliberately out of scope → `docs/04-prd.md` §9.

If still unclear, **ask the user before guessing**. The spec is dense for a reason.
